## A. この監査で直したもの（本番反映済み）

### A-1. 【critical】課金APIが誰でも叩ける状態だった → 塞いだ（`2647043`）

- VPS本番の `.env` は `APP_PASSWORD` が**空**。`_require_auth` は空なら素通しするため、**全ルートが無認証**。
  一方 `ANTHROPIC_API_KEY` / `ELEVENLABS_API_KEY` は設定済み。
- 既存のフェイルクローズドは条件が `os.getenv("RENDER")` ＝**Render専用**で、XサーバーVPSでは働いていなかった。
- **実証**: `curl https://ohanashi.bizsp.net/api/pack/start` → `{"ok":true}` で**10話ぶんの生成ジョブが起動**した
  （私の疎通確認で実際に起きた。`pm2 restart` で停止。ElevenLabsの音声ファイルは1本も書き出されず、
  実損は Anthropic の物語生成 2〜3回ぶん）。
- **対策**: `APP_PASSWORD` が空のときは `/api/` `/compare` `/pack` を **503** で閉じる。
  `/pro/`（こども画面）と静的配信は公開のまま＝子どもの利用に影響なし。本番で実測確認済み。

### A-2. 【high】「けってい」ボタンが画面に描かれていなかった → 直した（`f94266c`）

- `.q-foot` に `position`/`z-index` が無く、位置指定済みの `.paperbg`(z-index:0) が**上に描かれていた**。
  紙は `pointer-events:none` なので**タップは通る＝自動テストは全部PASSしていた**。
- 同種の事故を防ぐため、`.screen` 直下の子要素が全部 `position:relative; z-index:1` になっているかを
  ブラウザで機械監査した（現在は全画面OK）。

### A-3. 【high】設問で詰む／制限時間が全レベル15秒固定 → 直した（`f94266c`）

- 答えを選ばない限り先へ進めず、時間切れでも何も起きなかった → 「わからない → つぎへ」を常設。
- `TIME_LIMIT[q.level]` は設問データに `level` が無く常に undefined → **全レベル15秒**だった。

## B. 直したがまだ本番未反映（このあと反映）

### B-1. 【high・実測で確定】結果画面などでボタンに到達できず、ホームに戻れない

本番URLに対して7サイズで**到達性を実測**した結果（`scrollIntoView` しても画面内に入らない＝押せない）:

| 端末 | 画面 | 押せなかったボタン |
|---|---|---|
| iPhone SE1(320×568) | ホーム | 🌸がんばり / ⚙おうちのかた |
| iPhone SE1 | けっか（単発） | おうちへ |
| iPhone SE1 / SE / 14 | けっか（まちがいなおし8話） | **つづける / おうちへ** |
| iPhone 14 横向き | ホーム | まちがいなおし / がんばり / おうちのかた |
| iPhone 14 横向き | けっか（単発） | つぎの おはなし / おうちへ |

→ **まちがいなおしを数話やると、結果画面から二度と戻れない**（アプリを再起動するしかない）。
原因は `.home-body` / `.result-body` に `overflow:auto; min-height:0` が無く、
`position:fixed` の画面からはみ出した分に到達できないこと。

**修正後は 320×568 から iPad横まで7サイズ全画面で「押せないボタン0」を実測**。

## E. この監査で使った検証方法（再利用可）

- **到達性テスト**: 全画面のボタンを列挙 →「見えているか」「`scrollIntoView` で画面内に入るか」を7サイズで判定。
  今回の「押せないボタン」はこれで全部出た。**クリックできる＝OK、ではない**（Playwrightは自動スクロールするので見逃す）。
- **描画テスト**: `elementFromPoint` はボタンを返すのに**スクリーンショットに写らない**＝背景に隠れている、という判定。
- **データ検査**: マニフェスト252話に対して、正解IDと選択肢の対応・設問0件・場面0件を全数チェック。
